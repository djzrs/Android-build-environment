# 后台运行与悬浮窗

服务器从「Activity 里的一个对象」搬到了前台服务，顺便补了切后台时的地址悬浮窗。
本文记这一块的实现与踩坑。

## 为什么不是原来的做法

之前 `ServerViewModel` 拿着 `AppHttpServer`，`MainActivity.onDestroy()` 里 `stop()`。
问题是：Activity 一旦被回收（切后台久了被系统杀、划掉最近任务），服务器跟着没了。
用户看到的现象就是「APP 不在前台就访问不了」。

改成前台服务后：

- 服务器活在 `ServerService` 里，Activity 死活都不影响
- 通知栏常驻一条「局域网服务器运行中 + 地址」，带「停止」按钮
- 只有点停止（页面上或通知栏里）才结束

## 结构

```
server/
├── AppHttpServer.kt   NanoHTTPD，没变
├── ServerBridge.kt    状态单一来源（running / address / isLoopback / error）
├── ServerService.kt   前台服务，持有 AppHttpServer 与悬浮窗
└── ServerOverlay.kt   WindowManager 悬浮窗，显示地址、可拖、点击回 APP
AppVisibility.kt       APP 前后台状态（MainActivity.onStart / onStop 写）
```

- `ServerBridge` 是个 `MutableStateFlow`，服务写、UI 读（`collectAsStateWithLifecycle`）。
  以前服务器页和首页共享一个 ViewModel，现在它们只看这一个状态，谁都不持有服务器。
- `AppVisibility` 是服务被系统重建后仍能知道「APP 现在是不是在前台」的唯一途径。
  只看 `ServerService` 自己记的成员变量，重建后会退化成「认为在前台」，悬浮窗就不出来了。

## 悬浮窗

- 触发：`MainActivity.onStop()` → `AppVisibility` 变后台 → 服务 `overlay.show(address)`。
  回前台 `onStart()` 收起。**只要服务器在跑**才显示，没跑就不打扰。
- 权限：`SYSTEM_ALERT_WINDOW`，运行时要去系统设置里给。没权限就静默跳过——
  服务器本身由前台服务保着，不靠悬浮窗活着。
- 服务器页有一张「后台悬浮窗」卡片，显示授权状态，点了跳
  `ACTION_MANAGE_OVERLAY_PERMISSION`，回来后 `ON_RESUME` 刷状态。
- 内容：状态绿点 + 「局域网服务器」+ 地址（单行中间省略，最长 220dp）。
- 交互：点击卡片回 APP 并落到服务器页；拖超过 8dp 判定为拖拽，松手吸附到左/右边缘，
  **同时收成一颗 44dp 小球**（只留一个绿点），点小球展开回卡片（展开后再拖又收起）。
  贴上边还在挡内容的抱怨就出在这儿：吸附只挪位置不收尺寸，卡片一直横在那儿。
  右上角 × 只收悬浮窗，不停服务。
- 吸附细节：拖动时就把窗口限制在状态栏与导航栏之间的可用区域（`currentWindowMetrics` 去掉
  `systemBars` / `displayCutout`），甩不出屏幕；松手横向吸最近的那条竖边、留 8dp 边距，
  纵向只收敛边界（用户自己决定停多高），落位用 180ms 减速动画，不是瞬间跳。
- 落点与形态记在 `SharedPreferences`（`overlay_position`）：收起再弹出、服务被系统重建、转屏之后
  都回到上次的位置和形态，而不是跳回左边的默认高度、也不是又摊开一张卡片。
- 收起状态也落盘（`collapsed`）：收起过一次，下次切后台直接按小球出来，不用每次再往边上推。
- 卡片与小球叠在同一个 `FrameLayout` 里，切换只翻 `visibility`；`WRAP_CONTENT` 的窗口
  内容尺寸变了必须再 `updateViewLayout` 一次，否则部分机型仍按旧宽高画。
  收起/展开后要用 `doOnLayout` 等新尺寸量出来再去算贴边坐标，直接 `post` 会拿到旧的宽高。

## 通知

- 渠道 `html_manager_server`，`IMPORTANCE_LOW`（不响、不弹、不出横幅）。
- Android 13+ 需要 `POST_NOTIFICATIONS`，`MainActivity.onCreate` 里申请一次。
  用户拒绝不影响服务器运行，只是看不到那条通知。
- 前台服务类型用 `specialUse` 并写了 subtype 说明。`dataSync` 在 Android 15 起有
  6 小时/天的上限，一个常驻的本地服务器不适合被它掐掉。

## 踩坑

- **`startForeground` 必须在 5 秒内调用**：所以先把通知占上，再起 NanoHTTPD；
  起来后 `notify` 一次把地址刷进同一条通知，不新开第二条。
- **服务实例访问**：`ServerService.stop()` 走 `startService(ACTION_STOP)` 而不是
  直接 `stopService`，这样服务能自己 `stopForeground` + 清 `ServerBridge`；
  实例不在时直接清状态，不去拉起一个空服务（否则会短暂闪一条通知）。
- **悬浮窗泄漏**：`onDestroy` 里一定要 `overlay.hide()`，不然服务死了窗还挂着，
  只能重启手机。
- **悬浮窗的点击**：`OnTouchListener` 返回 true 会吃掉点击事件，
  所以手指没移动时手动 `performClick()`。
